PLAN STRUCTURÉ
======================================================================

1. Analyste
   Analyser la mission pour produire une spécification technique détaillée du problème FJSP dans le cadre du noyau minimal T-R-C-O. Identifier les éléments clés suivants :
- Structure de l'instance `InstanceTRCO` (tâches, ressources, précédences, compatibilités ressource-tâche, durées, échéances optionnelles).
- Contraintes à modéliser : précédences entre tâches, affectation unique d'une ressource compatible par tâche, non-chevauchement des tâches sur une même ressource, respect des échéances si présentes.
- Objectif : minimisation du makespan (date de fin de la dernière tâche).
- Hypothèses : `CompetenceRequise` est déjà validée en amont, `CompatibiliteRessourceTache` est la seule source de compatibilité et de durée.
- Livrable : un document structuré résumant les entrées, contraintes, et objectif du problème.

2. Architecte
   Concevoir le modèle CP-SAT pour le problème FJSP défini par l'Analyste. Détailler :
- Variables de décision : variables d'intervalle pour chaque opération (tâche + ressource compatible), variables booléennes pour l'affectation ressource-tâche, variable pour le makespan.
- Contraintes :
  - Chaque tâche est exécutée exactement une fois sur une ressource compatible.
  - Respect des précédences entre tâches.
  - Non-chevauchement des intervalles sur une même ressource.
  - Respect des échéances si présentes.
- Objectif : minimisation du makespan.
- Livrable : un schéma détaillé du modèle CP-SAT, incluant les variables, contraintes, et objectif, avec des exemples de code pour chaque partie (ex: création de variables, ajout de contraintes).

3. Développeur
   Implémenter la fonction `resoudre(instance: InstanceTRCO) -> Planning | None` en suivant strictement le modèle CP-SAT conçu par l'Architecte. Utiliser `ortools.sat.python.cp_model` pour :
- Créer les variables de décision (intervalles, booléennes, makespan).
- Ajouter les contraintes (précédences, affectation unique, non-chevauchement, échéances).
- Définir l'objectif de minimisation du makespan.
- Résoudre le modèle et extraire la solution sous forme de `Planning` si elle existe, sinon retourner `None`.
- Respecter les contraintes de sécurité (imports autorisés uniquement, pas d'accès réseau/fichier).
- Livrable : un module Python complet avec la fonction `resoudre` et les imports nécessaires.

4. Testeur
   Écrire des tests complémentaires pour valider la fonction `resoudre` sur des instances variées du FJSP, incluant :
- Une instance minimale avec 2 tâches et 1 ressource.
- Une instance avec précédences et plusieurs ressources compatibles.
- Une instance avec échéances.
- Une instance infaisable (ex: précédences cycliques ou échéances trop strictes).
- Une instance plus complexe (ex: 5 tâches, 3 ressources, précédences et échéances).
- Vérifier que le makespan est bien minimisé et que toutes les contraintes sont respectées.
- Livrable : un script de tests utilisant `unittest` ou `pytest` avec les cas de test décrits.

5. Reviewer
   Relire le code implémenté par le Développeur pour vérifier :
- La conformité au modèle CP-SAT de l'Architecte.
- Le respect des contraintes de sécurité (imports, pas d'accès interdit).
- La correction de la logique (variables, contraintes, objectif).
- La gestion des cas limites (instance infaisable, échéances).
- La qualité du code (lisibilité, modularité, typage).
- Livrable : un rapport de revue listant les points à corriger ou confirmer, avec des suggestions précises si nécessaire.

6. Debugger
   Corriger le code si le Reviewer ou les tests du Testeur identifient des erreurs. Se concentrer sur :
- Les bugs logiques (ex: contraintes mal implémentées, affectation incorrecte).
- Les erreurs de typage ou d'import.
- Les problèmes de performance critiques (ex: variables redondantes).
- Livrable : une version corrigée du module, avec un journal des corrections apportées.

7. Optimiseur
   Améliorer le code une fois validé, sans modifier son comportement. Optimisations possibles :
- Réduire le nombre de variables ou contraintes inutiles.
- Utiliser des méthodes plus efficaces pour ajouter des contraintes (ex: `AddNoOverlap` pour les ressources).
